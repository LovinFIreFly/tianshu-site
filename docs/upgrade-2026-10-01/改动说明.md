## 五、后端架构与性能

- **架构本质**：Flask 应用工厂 + 5 蓝图 + 纯 JSON 文件存储（db.py，mtime 进程内缓存，写时整份序列化 + 临时文件原子替换）+ waitress 8 线程 + Jinja SSR。
- **本轮落地**：
  - **gzip**：全站文本响应 >1KB 自动压缩（此前每页明文 ~186KB CSS + 37KB JS）；/static 30 天长缓存、/img 7 天 + 304。
  - **TTL 缓存**：get_settings（按文件 mtime）、stats(60s)、car_pool(15s)、dm_growth(60s)、static_v。
  - **消除 O(N²)/N+1**：car_pool 一次分组（原为首页/大厅/详情/车队详情反复全量算）；sessions_of 一次聚合；my_cars 预建索引；api_me、admin.users、growth、bookings/messages counts 全部单遍。
  - **写合并**：notify/audit 请求级缓冲 + teardown 一次性落盘（此前每发一条消息/日志都把 150KB notices.json / 75KB logs.json 整份重写）。
  - **发信异步**：验证码落库后 daemon 线程发邮件，接口立即返回。
  - **面板懒加载**：管理端/DM 首屏只算当前 tab（此前一屏渲染全部 14 面板，随数据量平方膨胀），切 tab 前端 fetch partial（tabs.js 已接线）。
  - **健壮性**：限流字典过期回收、UA 正则预编译、print→logging、waitress 8→16 线程。
- **未实施（需人工确认，详见 changelog-I 第四节）**：SESSION_COOKIE_SECURE（本机 HTTP 开发会登不上，建议按环境变量开关）、内置账号 123123 改密（现有账号会登录失败）、DEMO_CODE 上线前域名实测、poster 大图压缩（二进制资源）、字体自托管（模板域）、/m/api CSRF、后台列表服务端分页（需模板配合）。
